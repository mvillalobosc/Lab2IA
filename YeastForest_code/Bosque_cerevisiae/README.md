# Bosque_cerevisiae/ · YeastForest_code

[Español](#español) · [English](#english)

## Español

Esta carpeta tiene los tres scripts del bosque de *S. cerevisiae*. Cada uno escribe sus resultados en esta misma carpeta, sin subcarpetas, y el bosque lee sus entradas desde `DATA/` relativa al directorio de trabajo, así que conviene correrlos desde aquí y en este orden. El [README del proyecto](../README.md) explica el flujo completo y los datos de entrada.

| Script | Qué hace | Lee | Escribe |
| --- | --- | --- | --- |
| `bosque_SCerevisiae.R` | Construye el árbol neighbour-joining de referencia con todos los SNP bialélicos que pasan los filtros y un árbol por ORF con las mismas muestras, calcula RF y concordancia entre todos los pares y el respaldo de cada rama en el bosque. | `DATA/1011Matrix.gvcf.gz` y `DATA/SGD_features.tab` | `SCerevisiae_arboles.nwk` (línea 1 = referencia), `SCerevisiae_distancias_geneticas.csv.gz`, `SCerevisiae_RF.csv.gz`, `SCerevisiae_concordancia.csv.gz` y `SCerevisiae_resumen.tsv`; además `SCerevisiae_muestras_renombradas.tsv` si algún identificador del VCF no es válido en Newick |
| `clusters_SCerevisiae.R` | Agrupa los árboles de ORF con MST-kNN (los que `mst.knn` deja solos vuelven como grupos de un ORF) y prueba enriquecimiento hipergeométrico GO (BP, MF y CC) y KEGG por grupo, con FDR de Benjamini-Hochberg. | `SCerevisiae_RF.csv.gz` y `SCerevisiae_resumen.tsv` | `SCerevisiae_clusters.tsv`, `SCerevisiae_clusters_resumen.tsv` y `SCerevisiae_enriquecimiento.tsv` |
| `publicar_bosque.R` | Corre los análisis A (resolución como confusor de los grupos), B (umbrales de SNP y resolución), D (mapa gen-genoma de las ramas en conflicto con la referencia) y F (comparación con el bosque anterior por alineamientos). Importa las funciones de `bosque_SCerevisiae.R` con `PHYLO_LIBRARY_ONLY=1`, así que los dos archivos tienen que estar juntos. | los resultados del bosque y de los grupos, `cepas_cerevisiae.tsv` (en esta carpeta o en la de arriba) y `Arboles/<ORF>.nwk` | `SCerevisiae_pub_A_*`, `_pub_B_*`, `_pub_D_*` y `_pub_F_*`, once tablas en total |

`publicar_bosque.R` es idéntico al de [Bosque_eubayanus](../Bosque_eubayanus/): detecta la especie por el `<prefijo>_resumen.tsv` que encuentra en su carpeta. Las tablas que escribe aquí son `SCerevisiae_pub_A_resolucion_por_grupo.tsv`, `_pub_A_resolucion_pruebas.tsv`, `_pub_B_umbrales.tsv`, `_pub_B_umbrales_miembros.tsv`, `_pub_D_conflicto_por_orf.tsv`, `_pub_D_conflicto_tramos.tsv`, `_pub_D_conflicto_ramas.tsv`, `_pub_D_conflicto_por_grupo_cepas.tsv`, `_pub_D_conflicto_resumen.tsv`, `_pub_F_bosque_anterior_por_orf.tsv` y `_pub_F_bosque_anterior_resumen.tsv`.

Mientras corre, `bosque_SCerevisiae.R` guarda su avance en la carpeta oculta `.tmp_bosque_SCerevisiae`; si se interrumpe, la corrida siguiente retoma desde el último lote, y al terminar el script borra esa carpeta. Con `overwrite = FALSE` (el valor por defecto) no recalcula si los resultados ya existen. `workers` en `CONFIG` fija los procesos paralelos (2 por defecto; en Windows usa 1); si esa etapa se cae, el script avisa que suele ser falta de RAM y que conviene bajar `workers`. El script usa los paquetes de CRAN `ape`, `data.table`, `Matrix`, `Rcpp` y `digest` y los de Bioconductor `VariantAnnotation`, `Rsamtools`, `GenomicRanges`, `GenomeInfoDb`, `IRanges`, `SummarizedExperiment` y `S4Vectors`, y compila sus funciones de distancia con Rcpp, lo que exige un compilador de C++. `clusters_SCerevisiae.R` usa `data.table`, `igraph`, `mstknnclust`, `R.utils`, `AnnotationDbi`, `org.Sc.sgd.db`, `GO.db` y `KEGGREST`, y descarga las rutas KEGG, así que necesita internet.

Las carpetas `DATA/` (entradas) y `Arboles/` (el bosque anterior, un `<ORF>.nwk` por gen) no vienen en el repositorio, y el `.gitignore` de la raíz ignora esas carpetas, la carpeta temporal y todos los archivos `SCerevisiae_*` que escriben los scripts.

## English

This folder holds the three scripts of the *S. cerevisiae* forest. Each one writes its results in this same folder, without subfolders, and the forest script reads its inputs from `DATA/` relative to the working directory, so run them from here and in this order. The [project README](../README.md) explains the full workflow and the input data.

| Script | What it does | Reads | Writes |
| --- | --- | --- | --- |
| `bosque_SCerevisiae.R` | Builds the neighbour-joining reference tree with all the biallelic SNPs that pass the filters and one tree per ORF with the same samples, and computes RF and concordance for every pair and the forest support of each branch. | `DATA/1011Matrix.gvcf.gz` and `DATA/SGD_features.tab` | `SCerevisiae_arboles.nwk` (line 1 = reference), `SCerevisiae_distancias_geneticas.csv.gz`, `SCerevisiae_RF.csv.gz`, `SCerevisiae_concordancia.csv.gz` and `SCerevisiae_resumen.tsv`; also `SCerevisiae_muestras_renombradas.tsv` when a VCF sample ID is not valid in Newick |
| `clusters_SCerevisiae.R` | Groups the ORF trees with MST-kNN (trees that `mst.knn` leaves alone return as one-ORF groups) and tests hypergeometric GO (BP, MF and CC) and KEGG enrichment per group, with Benjamini-Hochberg FDR. | `SCerevisiae_RF.csv.gz` and `SCerevisiae_resumen.tsv` | `SCerevisiae_clusters.tsv`, `SCerevisiae_clusters_resumen.tsv` and `SCerevisiae_enriquecimiento.tsv` |
| `publicar_bosque.R` | Runs analyses A (resolution as a confounder of the groups), B (SNP and resolution thresholds), D (gene-genome map of the branches in conflict with the reference) and F (comparison with the earlier alignment-based forest). It imports the functions of `bosque_SCerevisiae.R` with `PHYLO_LIBRARY_ONLY=1`, so both files must sit together. | the forest and group results, `cepas_cerevisiae.tsv` (in this folder or the one above) and `Arboles/<ORF>.nwk` | `SCerevisiae_pub_A_*`, `_pub_B_*`, `_pub_D_*` and `_pub_F_*`, eleven tables in total |

`publicar_bosque.R` is identical to the one in [Bosque_eubayanus](../Bosque_eubayanus/): it detects the species from the `<prefix>_resumen.tsv` it finds in its folder. The tables it writes here are `SCerevisiae_pub_A_resolucion_por_grupo.tsv`, `_pub_A_resolucion_pruebas.tsv`, `_pub_B_umbrales.tsv`, `_pub_B_umbrales_miembros.tsv`, `_pub_D_conflicto_por_orf.tsv`, `_pub_D_conflicto_tramos.tsv`, `_pub_D_conflicto_ramas.tsv`, `_pub_D_conflicto_por_grupo_cepas.tsv`, `_pub_D_conflicto_resumen.tsv`, `_pub_F_bosque_anterior_por_orf.tsv` and `_pub_F_bosque_anterior_resumen.tsv`.

While it runs, `bosque_SCerevisiae.R` saves its progress in the hidden folder `.tmp_bosque_SCerevisiae`; if it stops, the next run resumes from the last batch, and the script deletes that folder when it finishes. With `overwrite = FALSE` (the default) it does not recompute when the results already exist. `workers` in `CONFIG` sets the number of parallel processes (2 by default; Windows uses 1); if that stage fails, the script warns that the usual cause is a lack of RAM and that `workers` should be lowered. The script uses the CRAN packages `ape`, `data.table`, `Matrix`, `Rcpp` and `digest` and the Bioconductor packages `VariantAnnotation`, `Rsamtools`, `GenomicRanges`, `GenomeInfoDb`, `IRanges`, `SummarizedExperiment` and `S4Vectors`, and it compiles its distance functions with Rcpp, which requires a C++ compiler. `clusters_SCerevisiae.R` uses `data.table`, `igraph`, `mstknnclust`, `R.utils`, `AnnotationDbi`, `org.Sc.sgd.db`, `GO.db` and `KEGGREST`, and it downloads the KEGG pathways, so it needs internet access.

The `DATA/` (inputs) and `Arboles/` (the earlier forest, one `<ORF>.nwk` per gene) folders are not in the repository, and the root `.gitignore` ignores those folders, the temporary folder and every `SCerevisiae_*` file the scripts write.
